# Sentiment Analysis Application - Project Report

## 1. Project Overview
This project is a PyQt6-based sentiment analysis tool explicitly designed for analyzing product reviews. It has evolved from a purely rule-based system into a **Hybrid Architecture** powered by State-of-the-Art (SOTA) Large Language Models (LLMs) to achieve superior semantic comprehension, context-awareness, and natural sarcasm detection. 

Instead of relying on hardcoded patterns for edge cases (like sarcasm or product malfunction phrases), the tool leverages HuggingFace's Generative AI for English and a fine-tuned Transformer classifier for Hindi. It retains NLTK's VADER and custom lexicons as a secondary subsystem for localized aspect breakdown and discrete emotion extraction.

## 2. Tech Stack and Libraries
- **Language**: Python 3.x
- **GUI Framework**: PyQt6
- **NLP Models (HuggingFace)**:
  - **English**: `Qwen/Qwen2.5-3B-Instruct` (Generative LLM invoked via `transformers` `pipeline("text-generation")` using `torch.bfloat16`).
  - **Hindi**: `cardiffnlp/twitter-xlm-roberta-base-sentiment` (Sequence Classifier invoked via `transformers` `pipeline("sentiment-analysis")`).
- **NLP Library (Lexicon & Tokenization)**: NLTK (VADER `SentimentIntensityAnalyzer`, `word_tokenize`, `sent_tokenize`).
- **Machine Learning Backend**: PyTorch (`torch`), `accelerate`.
- **Other Standard Libraries**: `os`, `re`, `string`, `json`, `deep-translator` (for language fallback).

## 3. System Architecture
The application is structured into clearly separated architectural layers:
- **UI Layer (PyQt6)**: Handles text area input, interactive missing-model dialogs (e.g., prompting the user to download the ~6GB Qwen model), result displays, and graphical progress bars indicating sentiment distribution and specific emotion intensity.
- **Sentiment Analyzer Router Class**: Manages model instantiation (lazy loading), language routing, and parsing logic.
- **Generative Inference Layer (English)**: Utilizes a rigorously crafted system/user prompt sent to the 3-Billion parameter Qwen model to intuitively evaluate sentiment, sarcasm, and negation in a single generative pass, returning structured JSON.
- **Classifier Inference Layer (Hindi)**: Uses XLM-RoBERTa for robust, native multilingual sequence classification without lossy translations.
- **Lexical Extraction Layer (VADER)**: Tokenizes sentences to calculate localized aspect sentiments ("quality", "price", "performance", etc.) and normalizes keyword frequencies for discrete emotion scoring (Joy, Anger, Fear, Sadness).

## 4. Code Structure
The workspace contains the following core files:
- `sentiment_analyzer.py`: Contains the `SentimentAnalyzer` class, which handles heavy resource management (HuggingFace model pipelines, NLTK `nltk_data` folder) and the core text processing pipeline (preprocessing, building LLM prompts, executing inference, sanitizing JSON outputs, and aspect/emotion analysis).
- `sentiment_ui.py`: Contains the `SentimentAnalysisApp` class, setting up the UI structure (headers, input sections, buttons, progress bars), and providing visual feedback alongside PyQt6 Message Boxes for downloading heavyweight ML models natively.
- `README.md`: Highly detailed documentation detailing the architecture, how the Hybrid approach works, and usage scenarios.
- `translation/`: A directory (or `deep_translator` fallback) handling translation for non-native languages into English to leverage the high-capacity Qwen generative model.

## 5. NLP Pipeline & Logic Flow
1. **Language Detection & Routing**: Determines if the text is English, Hindi, or another language (which triggers the translation fallback).
2. **Preprocessing**: Converts text to lowercase and standardizes whitespaces.
3. **Core Sentiment Inference**:
    - **English**: Constructs a zero-shot prompt instructing `Qwen2.5-3B-Instruct` to carefully analyze context, sarcasm, and product-specific idioms, strictly outputting a JSON object with `sentiment` and `confidence` keys.
    - **Hindi**: Passes text directly to `twitter-xlm-roberta-base-sentiment` for probabilistic label classification.
4. **Output Parsing & Sanitization**: For English, the router parses the generative output, strips potential Markdown formatting (` ```json ... ``` `) generated by the LLM, and loads it into a Python dictionary.
5. **Aspect & Emotion Extraction**: 
    - Splits text into individual sentences (`nltk.sent_tokenize`). 
    - Filters sentences against aspect lexicons (e.g., "design", "customer_service") and calculates specific sentiment scores for those slices.
    - Matches tokens (`nltk.word_tokenize`) against an emotion lexicon to generate a 0-100 normalized score for Joy, Anger, Fear, and Sadness.

## 6. Execution and Deployment
- The application can be executed either programmatically via CLI (`python sentiment_analyzer.py`) or via the GUI (`python sentiment_ui.py`).
- First-time setup dynamically provisions required NLTK resources locally (`nltk_data`) and interactively prompts the user to download HuggingFace models (cached into the system's `.cache/huggingface` directory for offline use).

## 7. Next Steps for AI / Contributors
An external AI or contributor can focus on the following high-impact improvements:
- **Quantization**: Implementing 4-bit or 8-bit quantization (`bitsandbytes`) for the `Qwen2.5-3B-Instruct` model to reduce the massive ~6GB VRAM/RAM footprint down to ~2GB for lower-end hardware.
- **LoRA Fine-tuning**: Fine-tuning the LLMs exclusively on product review datasets to guarantee strict JSON output structures without relying on prompting hacks and sanitization logic.
- **Batch Processing Optimization**: Adding PyTorch dataloaders and chunking logic for batch processing massive datasets of product reviews asynchronously (currently blocking the main thread during heavy inference).
- **Expanded Native Support**: Integrating more native HuggingFace pipelines for Spanish, French, German, etc., to reduce reliance on the generic translation fallback.
